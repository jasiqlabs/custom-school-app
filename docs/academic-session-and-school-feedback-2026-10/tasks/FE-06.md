# FE-06 — Concession description and safe adjustment semantics

**Trace to source:** Chat item 3; approved DLD requires nonretroactive assessed dues, current code differs.. **State and owner:** [TASK-TRACKER](../TASK-TRACKER.md) is authoritative. **Baseline files:** Student.concessionType/concessionValue, student.schema.ts, concession-calculator.ts, generate-dues.service.ts syncStudentConcessionDues. **No feature implementation implied by planning completion.**

## 1. Detailed requirement and use-case definition
**User story:** Operator can record why a fixed or percentage discount was offered and auditors can see when it was granted without unexpectedly changing paid history.

**Real school scenarios:** UC1: ₹900 tuition 10% scholarship for merit; reason saved with student and future charge. UC2: concession NONE clears active reason if chosen but old paid charges keep original concession snapshot. UC3: school grants new concession after August paid; August receipt unchanged and September follows rule. UC4: authorized retrospective correction posts a separate signed adjustment event, never rewrites an original receipt.

**Rules/eligibility/out-of-scope decisions:** Client decides required vs optional reason, whether discounts apply tuition only or all fee categories, and whether historical correction permitted. Preserve original type/value and unchanged paid invoice/receipt snapshots; code currently mutates pending due on profile change contrary to approved DLD. Must resolve via PRD/DLD governance, not simply extend mutation.

## 2. Detailed Level Design (proposed until approved by Harness)
**Persistent data model, uniqueness, indexing, migration:** Student.concessionReason nullable text max approved length, concessionPolicyVersion?; snapshot FeeCharge.concessionType,concessionValue,concessionAmount,reason? with private note separation; FeeAdjustment(id,chargeId,schoolId,amountDelta,reason,actorId,kind,state,createdAt) append-only with effective-date. Index student/charge and event audit.

**REST/port contract, actor authorization, DTOs and error semantics:** Student PATCH /operator/students/:id extends concession {type,value,reason?} with explicit NONE rules; GET student profile returns authorized reason; FeePublicFacade.previewConcessionChange returns affected future periods and optional adjustments. Validation of %<=100, discount not exceeding gross, sanitization.

**Backend workflow, module responsibilities, frontend states and integration strategy:** Manager edits concession in student profile, state shows current/forward effect; Students owns student-level preference via facade, Fees owns assessment/adjustment and recalculation where approved. Fees calculator uses exact decimal round-half-up, category applicability from approved policy, writes frozen reason snapshot on assessed charge. UI labels Description/Reason with helper.

**Race conditions, failure cases, transaction/retry/rollback semantics:** Old data has null reason; do not force migration fill. Private free text may contain protected data; restrict display to authorized manager and audit reason edits; never auto-print sensitive reason on public receipt unless agreed.
