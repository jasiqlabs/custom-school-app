# FB-01 — Public welcome page with one school-operator entry

**Source:** DOCX page 1 screenshot/feedback.. **Work status:** [single tracker](../TASK-TRACKER.md). **Approval required:** update Harness authority before implementation. **Current code / owner:** apps/web/src/app/page.tsx, home.module.css, admin/operator login screens.

## Business goal, concrete use cases and acceptance
**User story:** As a school visitor I see one friendly welcome action, 'Manage Your School', instead of choosing between Operator and Platform Admin panels.

**Use cases and expected results:** UC1: anonymous public home shows one green/primary link to operator login. UC2: platform administrator visits /admin/login through authorized direct URL and logs in successfully. UC3: keyboard-only user finds and activates CTA. UC4: deep-linked old panel URL remains reachable if authorized.

**Business policy and acceptance rules:** Hide Platform Admin CTA only on public homepage; do NOT delete or disable admin login/API. Keep GET DIGITAL YOUR SCHOOL brand. Responsive web first; no new login permissions implied.

## Detailed Level Design (proposed until approved)
**DB schema, indexes and migration/backfill:** No schema change. Frontend only replaces two portal-card layout with clear single-CTA welcome/hero; preserve alt text, link destination and accessibility semantics.

**API/routes/contracts, validation and authorization:** No new API. Existing /operator/login and /admin/login route guards must be unchanged; do not redirect /admin to /operator.

**Frontend screens, backend service orchestration, ports/facades and processing algorithm:** Next.js apps/web/src/app/page.tsx new hero + exactly one primary <Link href='/operator/login'>Manage Your School</Link>. CSS uses fluid spacing and max content width; account for portrait mobile widths and reduced-motion accessibility. Optional direct portal link hidden in public DOM; no link to /admin on landing.

**Errors, edge cases, reconciliation and recovery design:** Admin route should stay secure independently of discoverability; static site may expose JS routes but authorization must be server-enforced. No visual reliance on emojis/icons. Preserve current branding assets.
