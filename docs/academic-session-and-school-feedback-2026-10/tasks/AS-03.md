# AS-03 — Session-aware student enrollment and preserved history

**Authority:** PDF clarifications 1 and 10 (pages 2/4). **Status:** see [single task tracker](../TASK-TRACKER.md). **Required approval:** client scope + Harness PRD/HLD/story/UIUX/DLD revision. **Relevant current code:** Student, StudentEnrollment, Class, Section prisma models; student admission, profile, search, print, TC snapshot.

## 1. Requirement and operator story
As a school staff member, I can see which class/section a student belonged to in each academic year even after a promotion or transfer.

**Use cases with expected outcomes:** UC1: same student ID enrolled in Nursery A (2026–27), LKG B (2027–28). UC2: parent requests old admission form or TC for previous year. UC3: current class renamed and prior-year print must preserve originally recorded label. UC4: import legacy rows without clear session with operator reconciliation screen.

## 2. Exact functional acceptance boundaries
Student UUID is stable; Enrollment is owned history of class/section within exact session and date range. One valid current enrollment for active session per student. Distinguish status of student (active/left) from enrollment period closure. Closed session enrollment cannot be overwritten on routine edit.

## 3. Detailed technical design — data, contracts, algorithm and UI

**Ownership and persistence / migrations:** Add StudentEnrollment.academicSessionId nullable initially, endedReason, effective dates and class/section name snapshots; composite same-school FK to AcademicSession(schoolId,id). Partial unique active enrollment index on (schoolId,studentId,academicSessionId) and temporal-overlap protection with approved rules. Migrate via legacy map table and verified backfill; only make FK non-null once all rows explicitly mapped.

**API and typed validation:** Existing /operator/students listing/profile/admission-form take optional academicSessionId with server validated school/session ownership; add GET /operator/students/:id/enrollments?academicSessionId. POST admission includes active session selection/inference; return explicit sessionId and enrollmentVersion in response.

**Service algorithm, cross-module integrations, frontend screen state:** Students aggregate owns enrollment writes; AcademicsPublicFacade validates year and writable state; class/section verified same-school before INSERT. History queries use saved name snapshots where appropriate. Web student directory/session selector and history timeline render current/historic period separately. TC obtains StudentsPublicFacade.snapshotAtSession rather than querying student tables.

**Edge cases, consistency and recovery:** Backfill cannot infer old class from current class if history absent; mark 'legacy unverified' until school confirms. Reenrollment after returning must not steal prior row. No constraint implying only one enrollment over all years in new design.

## 4. Verification matrix (named tests)

**Frontend (FE) test plan:** TC-AS03-FE01 switch 2026–27 to 2027–28 in profile, show different class; FE02 old-year read-only; FE03 student with unclassified legacy history shows 'Review required'; FE04 print headers correct year; FE05 responsive timeline.

**Backend (BE, DB, integration, API, security) test plan:** TC-AS03-BE01 composite FK and partial uniqueness; BE02 same-school scope on session/class/section/student; BE03 concurrent registration prevents duplicate; BE04 historical print immutability; BE05 legacy migration replay/idempotency; BE06 class rename doesn't alter saved year snapshot.

**Nonfunctional (NFR, load, reliability, privacy, accessibility) test plan:** TC-AS03-NFR01 student code p95 <1s at 5000 students, name p95<1.5s inherited; NFR02 bounded server pagination/indexes; NFR03 no loss of existing enrollments; NFR04 audit metadata privacy & backups.
