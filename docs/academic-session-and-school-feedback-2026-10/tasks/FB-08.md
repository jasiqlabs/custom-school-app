# FB-08 — Two operator roles and server-enforced capabilities

**Evidence:** DOCX page 5; original API has no operator role. **Execution:** [TASK-TRACKER](../TASK-TRACKER.md). **Authority:** Proposed only until PRD/HLD/story/UIUX/DLD gates approved. **Current touch points:** SchoolOperator Prisma, OperatorsService, OperatorGuard, SessionService and web operator/admin screens.

## Requirement, actors, real-world use cases
**Business story:** Platform administrator provisions a Type 1 report viewer or Type 2 manager, and every server operation checks capabilities, even if browser UI is bypassed.

**Use cases and acceptance examples:** UC1: existing operators retain full functionality after migration. UC2: new REPORT_VIEWER can view allowed reports. UC3: existing manager is downgraded while logged in; old token immediately loses write rights. UC4: report viewer attempts TC issue with endpoint direct URL; 403. UC5: manager cannot access /platform admin routes.

**Business invariants, eligibility, scope and denial conditions:** MANAGER=full school-operations capability, not cross-school administration. REPORT_VIEWER=approved reports only. Default DENY for any new endpoint without declared ability. Do not couple capability to school status; both school status and role must pass. Password reset/deactivation still revokes sessions.

## Detailed design: domain, schema, interfaces and UI
**Database schema / constraints / existing-data migration:** SchoolOperator.role enum REPORT_VIEWER|MANAGER default MANAGER for backfill only; capability registry codes in type-safe contract; session includes roleVersion or compare SchoolOperator.accountVersion on every privileged call. On role update bump accountVersion+revoke all user sessions transactionally; store audit old/new role.

**Exact proposed endpoint contract, input/output, role/tenant validation:** Existing POST/PATCH /platform/schools/:id/operators accept role, role appears in GET list; PATCH role dedicated version guard; GET /operator/me/capabilities returns allow list and school identity. Capability guard uses @RequiresCapability('students.write' etc) and actor school, CSRF separately. 403 forbidden vs 404 foreign record. Never let manager choose own role.

**Service algorithm, module ownership and external integration / UI flow:** Admin operator add/edit form selection, explanatory labels and default appropriate role; server role update invalidates session. Extend OperatorGuard to resolve identity but leave capability authorization in dedicated guard covering every controller operation, including downloads/GET private profiles. Web header/nav built from validated me/capabilities; server pages auth-gated too.

**Concurrency, edge cases, failure handling and idempotency:** Backfill on live tenants must retain existing operators, avoid null role fail-open, preserve admin/operator authentication plane split. Last active operator deletion policy unchanged. New routing approach must not bypass CSRF.

## Verification plan with task-specific case IDs
**Frontend (FE) cases:** TC-FB08-FE01 admin create/edit role; FE02 forced re-login after downgrade; FE03 old operator sees same navigation; FE04 report-viewer no fee collect; FE05 responsive/keyboard.

**Backend (BE) cases:** TC-FB08-BE01 migration defaults existing to MANAGER; BE02 each controller route coverage test; BE03 stale cookie after downgrade denied; BE04 direct API invalid capability; BE05 cross-school and admin segregation; BE06 reset/deactivation unchanged.

**Non-functional (NFR) cases:** TC-FB08-NFR01 measurable guard overhead at 50 parallel requests; NFR02 deny-by-default regression scanner; NFR03 authorization audit with no PII; NFR04 zero session revocation race.

## Backwards compatibility, release gates and acceptance
Existing school login/admin routes, student imports, monthly fee configuration/collection/void, transport, documents and reports must continue to work. Apply tenant-scoped auth, CSRF, auditable mutations, no-store sensitive responses, 7-year retention policy and additive DB migration/rollback rehearsal. Run two-tenant seeded integration tests and show E2E acceptance on mobile/tablet/desktop web. Implement behind staged release flags when schema/financial change is involved. **Definition of done:** Exhaustive route inventory signed by security reviewer, both roles and session downgrade end-to-end proven. Reviewer attaches FE/BE/NFR results, PR and release record to [tracker](../TASK-TRACKER.md); do not assert completion on this planning branch.
