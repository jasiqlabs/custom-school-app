# DC-04 — Fee-clearance rules for Admit Card issuance (part of paid CR)

**Source:** Chat item 2; **Commercial gate:** same as DC-03. **Status:** only [tracker](../TASK-TRACKER.md).

## Requirement and examples

An admit card cannot be newly generated for a student who owes any fee deemed relevant by the **approved exam policy**. Policy must say whether prior months/years, transport, books, current term, future dues and fine count, and which exam date is cutoff. Do not assume all annual fees become payable early.

- **UC-01:** ₹300 overdue under exam's fee cutoff → student blocked and included in safe blocked list.
- **UC-02:** Second student fully clear → issued independently in same batch, if partial batch allowed by client.
- **UC-03:** Payment made just before issue → server validates current ledger, not UI cache.
- **UC-04:** Payment void after card issued → old card remains historical, new issue follows restored due balance.
- **UC-05:** Direct API and scheduled worker cannot bypass fee gate.

## Detailed technical proposal

**Ownership:** Documents/AdmitCard issue workflow invokes shared `FeesPublicFacade.checkDocumentClearance` from DC-02 with `purpose:ADMIT_CARD`, validated `examContextId`, school/session identity, `asOfDate`, versioned policy id. Fees owns all category eligibility, adjustments, prior-year charges and opening balances.

**Data:** `ClearancePolicy(id,schoolId,purpose,cutoffRule,eligibleCategoryIds,includePriorSessions,version,activatedAt)` if configurable per school/exam; `DocumentClearanceDecision` or immutable decision snapshot linked to AdmitCardIssue (student, exam, amount, revision, date, policy version). Avoid nullable magic 'feesCleared' flags that can become stale.

**API:** `FeesPublicFacade.batchCheckDocumentClearance({schoolId,studentIds,purpose:'ADMIT_CARD',examContextId,asOfDate,policyVersion})` returns ordered `eligible[]`, `blocked:[{studentId,amount,periods}]`, `ledgerRevisionPerStudent`. `POST /operator/admit-cards/issue` rejects or partially completes per **approved policy** and records failed eligibility without creating a PDF job for blocked IDs. Returned errors 409 ERR_FEES_PENDING_FOR_ADMIT_CARD; no PII.

**Consistency:** Immediately before creating issue/job verify ledger revision under lock or through a domain-approved transaction boundary/serializable check. If batch long-running, recheck each student before commit; limit chunk size. If a new charge posts concurrently, deterministic retry/fail closed. Worker must never independently create card when no authorized issue record exists. Cache only for UI, not issuance decision.

**FE:** Student eligibility table with total pending, categories/cutoff explanation and 'View/Pay Fees' link for MANAGER, disabled Generate for pending; warn user when statement refresh required. Never show debt of another tenant.

**Approval questions:** All sessions vs current? Exam cutoff calendar date? Whether future months need prepayment? Which categories? Exemptions? Whether batch skips blocked or rejects whole batch? Must be decided with client and separate CR approval.
