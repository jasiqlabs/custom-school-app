# AS-06 — Year selectors and session-aware views, exports and documents

**Authority:** PDF clarifications 1,10 (pages 2/4). **Status:** see [single task tracker](../TASK-TRACKER.md). **Required approval:** client scope + Harness PRD/HLD/story/UIUX/DLD revision. **Relevant current code:** Operator shell, Student/Fees/Dashboard/TC DTOs, current class APIs.

## 1. Requirement and operator story
As a manager or approved report viewer, I select a school year and see data from that year, with current year default and historical records protected.

**Use cases with expected outcomes:** UC1: 2026–27 selection shows historical class and payments; UC2: switch to 2027–28 and see current student directory; UC3: export title/file metadata includes year; UC4: view-only operator can only see explicitly permitted reports regardless of year; UC5: invalid session deep link is denied.

## 2. Exact functional acceptance boundaries
Select valid school-owned session; one ACTIVE default from DB; no time-of-day/current calendar inference; closed-year writes blocked at API. 'All years' overview only where business approves. Page caches must include tenant+session+role.

## 3. Detailed technical design — data, contracts, algorithm and UI

**Ownership and persistence / migrations:** No duplicate session table. Read models include schoolId, academicSessionId, immutable originSessionId of fee lines, requestedAsOf. Bounded aggregates and school+session indexes. Historic report filter persisted with audit job metadata.

**API and typed validation:** Optional validated academicSessionId query on student directory/profile/admission print, fee statement/pending/exports, dashboard period; common envelope {academicSession:{id,code,status},asOfDate,data}. Retain old URLs with safe active-year default for backwards compatibility.

**Service algorithm, cross-module integrations, frontend screen state:** Shared session context selector in operator header, URL query or safe context storage, server revalidates each request; each consuming domain resolves through AcademicSessionPublicFacade and formats selected year. Historic routes show clear read-only badge and export permissions.

**Edge cases, consistency and recovery:** Do not add exams/attendance to MVP just because those may eventually need a session key; admit cards are gated CR. Deactivating school does not erase historical screens for authorized admin.

**Frontend (FE) test plan:** TC-AS06-FE01 selector changes all relevant pages without stale cards; FE02 reload/share preserves valid selection; FE03 current default; FE04 closed-year read-only; FE05 export title/header; FE06 responsive menu and accessible keyboard.

**Backend (BE, DB, integration, API, security) test plan:** TC-AS06-BE01 foreign school session ID 404; BE02 all paginated queries include year; BE03 role bound exports and cached results; BE04 current fallback when no session/legacy tenant compatibility; BE05 no monthly fee re-query invalid grouping.

**Nonfunctional (NFR, load, reliability, privacy, accessibility) test plan:** TC-AS06-NFR01 cache poison/tenant leakage; NFR02 query p95 against approved search/dashboard targets; NFR03 5k student export streaming; NFR04 WCAG 2.1 AA tab/contrast, no-store private reports.
