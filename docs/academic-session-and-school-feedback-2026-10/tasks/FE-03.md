# FE-03 — Transport, exam, late and other fee charge types

**Evidence:** Chat item 4. **Execution:** [TASK-TRACKER](../TASK-TRACKER.md). **Authority:** Proposed only until PRD/HLD/story/UIUX/DLD gates approved. **Current touch points:** transports assignment service; FE-01 rule catalog; FE-07 ledger; student status/fee eligibility CL-02.

## Requirement, actors, real-world use cases
**Business story:** Operator can record appropriate transport, exam, late and custom other dues with correct cadence and no duplicate assessment.

**Use cases and acceptance examples:** UC1: enrolled transport student charged valid route fee only while service active. UC2: once-per-term exam charge label 'Annual Exam' without full exam result module. UC3: manager manually records permitted late fee with reason, without auto-fine. UC4: Other category with memo/amount. UC5: fee update after transport ends does not delete past charges.

**Business invariants, eligibility, scope and denial conditions:** Automatic transport/exam/late billing rules remain blocked until client approves triggers and coverage. Late fees should default manual (no automatic penalty). Transport assignment ownership belongs Transport, fee assessment Fees. Exam fee does not entail creating whole exam module or admit card.

## Detailed design: domain, schema, interfaces and UI
**Database schema / constraints / existing-data migration:** FeeRule supports charge basis/servicePeriod, examEventRef? (simple approved label, not grades), transportAssignmentId? as source reference, FeeCharge.originReference and reason, sourceKey unique by applicable school/student/event/month/category. Provide indexes for service validity windows.

**Exact proposed endpoint contract, input/output, role/tenant validation:** Manager POST /operator/fees/charges/manual {studentId,categoryCode,reason,amount,eventLabel?,dueDate}; GET fee rules and eligible transport source summaries via TransportPublicFacade; finance service validates max/min amount and school category, auth and audit.

**Service algorithm, module ownership and external integration / UI flow:** Fees engine batch requests active service eligibility periods from TransportPublicFacade; calculates school-configured amount per approved dates; for Exam and Other show labeled form; Late manual requires extra reason. UI category selector dynamically shows only relevant fields, a preview table and post-confirm updated statement.

**Concurrency, edge cases, failure handling and idempotency:** Student exits during charge period; need agreed prorating and future cutoff CL-02. Avoid charging transport to student with 'transportRequired' YES but no assignment if policy says actual service only. Do not issue exam admit card automatically.
