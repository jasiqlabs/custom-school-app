# FE-01 — Configurable fee category catalog and fee rule engine

**Evidence:** Chat item 4 categories list; impacts approved monthly-fees PRD. **Execution:** [TASK-TRACKER](../TASK-TRACKER.md). **Authority:** Proposed only until PRD/HLD/story/UIUX/DLD gates approved. **Current touch points:** prisma ClassFeeConfig, FeeDue; ConfigureFeeService, fee setup UI and Zod fee contracts.

## Requirement, actors, real-world use cases
**Business story:** A school manager configures monthly tuition plus registration, admission, transport, exam, late, books, uniform and 'other' charge rules without manually editing databases.

**Use cases and acceptance examples:** UC1: create registration rule ₹500 one-time and tuition ₹900 monthly; UC2: add exam fee ₹300 per approved term; UC3: edit fee rule for future period without changing paid old charges; UC4: disable fee category but historical balance remains visible. UC5: same school two classes have different tuition.

**Business invariants, eligibility, scope and denial conditions:** Fee category is classification, fee rule controls who/when/how much; school-scoped configurable amounts and labels. Original monthly model must remain compatible. Category uniqueness by normalized code; no hardcoded charge amounts. Auto late fee forbidden without policy approval. Book/uniform not inventory.

## Detailed design: domain, schema, interfaces and UI
**Database schema / constraints / existing-data migration:** FeeCategory(id UUID,schoolId,code,displayName,chargeKind ONE_TIME|RECURRING|EVENT|MANUAL,status,version); FeeRule(id,schoolId,categoryId,academicSessionId?,classId?,amount numeric(12,2),effectiveFrom,validUntil?,recurrencePolicy,paymentDueOffset?,version,status); check amount>=0 for optional waiver and >0 for active billed rule per approved policy; UNIQUE school/category normalized code; indexed school,class,session,date. Legacy ClassFeeConfig mapped in compatibility read adapter.

**Exact proposed endpoint contract, input/output, role/tenant validation:** GET/POST/PATCH /operator/fees/categories, GET/POST/PATCH /operator/fees/rules with positive amount Zod, dates/year restrictions, role manager; GET list full rule projections for FE; 422 invalid recurrence/currency, 409 stale version/dup, 404 tenant conflict.

**Service algorithm, module ownership and external integration / UI flow:** Fees module owns rule resolution: choose one applicable rule by school+session+class+category+effective date, handle override precedence explicitly; billing engine FE-07 creates idempotent charge sourceKey; UI Fee Setup tab categories+rules, activate/deactivate with preview of who will be affected; dashboard aggregates through FeesPublicFacade.

**Concurrency, edge cases, failure handling and idempotency:** Class/month rate change retroactivity must obey approved DLD frozen due snapshots; do not silently recalculate paid or prior generated due when editing rule. Safe path is adjustment with reason and audit if approved. Multiple event charges in same month should coexist without overwriting each other.
