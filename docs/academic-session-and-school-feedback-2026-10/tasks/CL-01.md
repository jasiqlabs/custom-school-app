# CL-01 — Unified leaving, TC, pass-out and transport/fee lifecycle

**Authority:** PDF clarification 4 (page 2) — NEW gap missing from 26 tasks. **Status:** see [single task tracker](../TASK-TRACKER.md). **Required approval:** client scope + Harness PRD/HLD/story/UIUX/DLD revision. **Relevant current code:** Student status service, TC issue service, TransportPublicFacade, FeesPublicFacade, enrollment service.

## 1. Requirement and operator story
As a school manager, I record when a student leaves or passes out, with an effective date, so current roster and future service charges stop while historical dues and documents remain intact.

**Use cases with expected outcomes:** UC1: student leaves with TC after fees clear; recorded leaving effective 2027-02-15, no March recurring tuition or transport. UC2: student leaves without TC, exit recorded with reason. UC3: student passes out, last enrollment closes and no new charge. UC4: TC issued for historic context without automatic exit unless approved. UC5: interrupted fee-stop step retries safely.

## 2. Exact functional acceptance boundaries
Client must decide whether TC issuance **automatically** marks Left; no default coupling. Future charge eligibility ceases from agreed effective date; already-assessed debt is never deleted; termination of transport is date-effective; student can return only via CL-04 workflow.

## 3. Detailed technical design — data, contracts, algorithm and UI

**Ownership and persistence / migrations:** Add StudentExitEvent(id,schoolId,studentId,sessionId,effectiveDate,reason,exitType LEFT|TRANSFERRED|PASSED_OUT,tcId?,state PENDING|APPLIED|FAILED,createdBy,version) and durable workflow state/outbox; record StudentEnrollment.endedReason,endedAt effective; transport's serviceEndDate updated by its owner; fee accrual stop policy stored as domain eligibility event, no direct fee table update by Students.

**API and typed validation:** POST /operator/students/:id/exit/preview {effectiveDate,reason,type,issueTc?:boolean}; POST /operator/students/:id/exit {reviewToken,idempotencyKey}; GET /operator/students/:id/exit-history. Optional 'Issue TC' invokes DC-01/02 via document facade only after clearance and policy; returns 409 when blocked.

**Service algorithm, cross-module integrations, frontend screen state:** Explicit coordinator owned by student lifecycle (not TC controller) requests preview from transport and fees facades, validates session and clearance policy, persists ExitWorkflow, calls individually idempotent domain commands via outbox; finalize student only after future billing/transport closure acknowledged; errors visible as retryable, no cross-module repo writes. UI guided review shows stopping future services and retaining unpaid balances.

**Edge cases, consistency and recovery:** Partial month if student leaves mid-month unresolved (CL-02). TC issued to alumnus does not imply an unapproved status transition. Older existing TC unaffected. Avoid deadlocks via stable per-student lock order and outbox if multi-service commit can't be atomic.

## 4. Verification matrix (named tests)

**Frontend (FE) test plan:** TC-CL01-FE01 leave-without-TC, leave-with-TC, pass-out previews; FE02 unpaid TC rejected yet allowed exit without TC if approved; FE03 exit history and reversals visible; FE04 failure repair CTA; FE05 stopped transport banner.

**Backend (BE, DB, integration, API, security) test plan:** TC-CL01-BE01 overlapping exits idempotent; BE02 TC clearance cannot be bypassed; BE03 no fee generated after effective stop; BE04 already assessed arrears preserved; BE05 transport end effective; BE06 404 foreign-school student; BE07 same student return uses CL-04.

**Nonfunctional (NFR, load, reliability, privacy, accessibility) test plan:** TC-CL01-NFR01 kill worker at each outbox step and recover; NFR02 auditor trail without PII; NFR03 no long cross-domain DB transaction; NFR04 replays zero extra charged months and stale cache invalidation.
