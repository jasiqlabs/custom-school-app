# FB-04 — Optional Aadhaar with secure nullable profiles and bulk-import compatibility

**Source:** DOCX page 2. Conflicts with approved PRD FR-STU-001 Aadhaar required; approve revision.. **Work status:** [single tracker](../TASK-TRACKER.md). **Approval required:** update Harness authority before implementation. **Current code / owner:** students/student.schema.ts, StudentDomainValidator, AdmitStudentUi, StudentPrivateProfile, student-import.service.ts.

## Business goal, concrete use cases and acceptance
**User story:** As an operator, I can admit a pupil when Aadhaar is unavailable, without entering a fake number, and may add a valid Aadhaar later.

**Use cases and expected results:** UC1: submit all other mandatory fields with blank Aadhaar: success. UC2: submit valid Aadhaar: encrypted and only last4 masked. UC3: nonblank invalid checksum: rejected. UC4: import mixed spreadsheet (blank/valid/invalid) with clear row results. UC5: previously encrypted student still displays masked last4, and update can deliberately remove Aadhaar with audit.

**Business policy and acceptance rules:** Missing Aadhaar is null, not zeroes or synthetic value. If supplied, keep existing Verhoeff checksum and encrypted profile policy. Null should be valid in manual admission, patch, import, view, TC/admission print, exports. Never reveal raw Aadhaar to report-viewer.

## Detailed Level Design (proposed until approved)
**DB schema, indexes and migration/backfill:** ALTER StudentPrivateProfile.aadhaarLast4 DROP NOT NULL; encryptedPayload schema changes to nullable aadhaarNumber with version-aware decrypt backward compatibility; preserve old fields and encryption key version. StudentPrivateProfile row can still contain other PII without Aadhaar; no unnecessary delete.

**API/routes/contracts, validation and authorization:** Zod studentAdmissionSchema aadhaarNumber optional/nullable/''->null, patch allows not-supplied vs explicitly null (remove) distinction. Domain validateAadhaar returns masked helper only for populated value; DTO aadhaarMasked nullable or 'Not provided' UI projection. XLSX header 'Aadhaar (Optional)', accept old template version.

**Frontend screens, backend service orchestration, ports/facades and processing algorithm:** Admission front-end remove required asterisk and blank hard check; backend validator skip only empty; safe encryption and last4 persistence conditional. Import parser old and new headers maps optional column, no error when blank, per-row error for bad supplied value; profile/edit and print components handle missing value without undefined crashes.

**Errors, edge cases, reconciliation and recovery design:** Treat whitespace/partial numbers as invalid if not truly blank. Masking helper must not crash on null. Sensitive data may be present in legacy encrypted import preview; keep current no-store and audit. Check PAN/bank unaffected.
