# FB-07 — Reports-only operator access

**Evidence:** DOCX page 5 two operator types. **Execution:** [TASK-TRACKER](../TASK-TRACKER.md). **Authority:** Proposed only until PRD/HLD/story/UIUX/DLD gates approved. **Current touch points:** session.guard.ts OperatorGuard, all operator controllers, operator nav, report/export endpoints.

## Requirement, actors, real-world use cases
**Business story:** School owner assigns Operator 1 who can only view authorized reports and download them, but cannot edit or see sensitive student profiles.

**Use cases and acceptance examples:** UC1: a reports-only operator logs in to a reports-oriented navigation. UC2: downloads permitted month-wise fee XLSX for own school. UC3: POST fee collection returns 403 even via curl with valid login+CSRF. UC4: GET arbitrary student private profile not allowed. UC5: tenant B report URL cannot be fetched by tenant A.

**Business invariants, eligibility, scope and denial conditions:** 'View all Reports' must be translated into explicit report allow-list and allowed columns; not 'all GET requests'. Non-report modules e.g. student entry/transport editing should not be exposed. All privileged admin routes stay platform-only. Client must confirm list of reports and PII visibility.

## Detailed design: domain, schema, interfaces and UI
**Database schema / constraints / existing-data migration:** SchoolOperator.role enum REPORT_VIEWER|MANAGER from FB-08; capability matrix REPORTS_READ and REPORTS_DOWNLOAD, optionally report-specific scopes if confirmed. No direct access to StudentPrivateProfile; job/report rows bind schoolId and authorized actor with private file permission.

**Exact proposed endpoint contract, input/output, role/tenant validation:** GET /operator/reports/* and GET authorized export status/download restricted to reports.read/download; POST config/payment/student/transport/promotion/TC always 403. Legacy operator GET routes treated as sensitive until reviewed; deny-by-default. For new reports API use server projection from approved report facades.

**Service algorithm, module ownership and external integration / UI flow:** Use capability guard/decorator on each report route and secure file resolution; nav server-derived capability DTO. Dashboard should not accidentally count as all reports unless approved. Link accessible 'Download' only for report resources. Role changed during session triggers invalidation from FB-08.

**Concurrency, edge cases, failure handling and idempotency:** No client-side role flag as authority, no hiding bypass; export job must re-check permission at download time. Audit denied write attempts without exposing sensitive inputs. Report filtration as-of session applies AS-06.
