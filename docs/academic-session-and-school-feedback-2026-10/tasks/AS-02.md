# AS-02 — Activate, close, lock and correct academic sessions

**Authority:** PDF clarification 3 (page 2), 1 (page 2). **Status:** see [single task tracker](../TASK-TRACKER.md). **Required approval:** client scope + Harness PRD/HLD/story/UIUX/DLD revision. **Relevant current code:** AcademicsSession (AS-01); existing class/student/fees read facades; audit and session guards.

## 1. Requirement and operator story
As an authorized manager, I activate one year, preview year-end blockers, close it after review, and preserve historical records for correction-only access.

**Use cases with expected outcomes:** UC1: activate 2026–27 while future 2027–28 remains DRAFT. UC2: two operators concurrently try to activate different years. UC3: close-preview shows students pending promotion and fees unresolved without deleting debts. UC4: print old report after CLOSED, while edit attempt is denied. UC5: exceptional correction is auditable and restricted.

## 2. Exact functional acceptance boundaries
One ACTIVE session per school at database level, irrespective of concurrent calls. Do not mark any pending fee paid on close. 'CLOSED' is read-only; corrections should append audit/adjustment rather than change issue-time snapshots. A school's workflow for open-next vs close-old is subject to approval; no implicit auto-rollover.

## 3. Detailed technical design — data, contracts, algorithm and UI

**Ownership and persistence / migrations:** Use Session.status transitions DRAFT→ACTIVE→CLOSING→CLOSED with version/check constraint and partial UNIQUE(schoolId) WHERE status=ACTIVE. SessionTransitionLock/CloseReview snapshot can be derived; store approval actor, time and decision hash for confirmed close when necessary. Add indexes(schoolId,status,startDate).

**API and typed validation:** POST /operator/academic-sessions/:id/activate {expectedVersion}; GET /operator/academic-sessions/:id/close-preview; POST /operator/academic-sessions/:id/close {expectedVersion,reviewToken,confirmation}; authorized correction endpoint only after ADR, otherwise no reopen endpoint.

**Service algorithm, cross-module integrations, frontend screen state:** Lock school row in transaction, verify target school and no concurrent active year, transition state+audit in same transaction. Close preview fetches bounded counts via StudentsPublicFacade, FeesPublicFacade and TransportPublicFacade; close repeats versioned checks before commit and records accepted warnings. Shared ClosedPeriodGuard in domain write paths; UI displays reasons without enabling forbidden historical edits.

**Edge cases, consistency and recovery:** A formal closed year must not block collection against prior obligations if approved; paid old debts should be appended as new dated allocation, not edit previous class/enrollment snapshots. If close fails on stale preview, return review refresh, not force close.
