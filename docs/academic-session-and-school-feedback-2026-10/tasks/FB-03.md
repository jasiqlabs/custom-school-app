# FB-03 — Deprecate student-level UDISE control; school codes on official documents

**Source:** DOCX page 1, student admission and TC screenshots.. **Work status:** [single tracker](../TASK-TRACKER.md). **Approval required:** update Harness authority before implementation. **Current code / owner:** student admission UI/service, SearchStudentsService.getAdmissionFormPrint, TcService snapshot, tc-pdf-builder.ts.

## Business goal, concrete use cases and acceptance
**User story:** As a school operator, I no longer see misleading 'UDISE Code' inside each student's Academic Enrollment; official school identifiers appear on admission form and newly issued transfer certificates.

**Use cases and expected results:** UC1: admit a child without student UDISE entry. UC2: printed admission form includes school 3 codes. UC3: a newly issued TC includes same codes in immutable school snapshot; historical TC PDF stays byte-identical. UC4: existing student.legacy udise field remains stored for controlled migration.

**Business policy and acceptance rules:** Remove student UDISE from UI, not automatically DROP data column or erase existing values. School codes come from school settings; old documents are never re-rendered without new issuance identity. School code missing should show no misleading placeholder; readiness optional until client approval.

## Detailed Level Design (proposed until approved)
**DB schema, indexes and migration/backfill:** No immediate DROP Student.udiseCode; mark deprecated in contracts when safe. TC encrypted snapshot.school extends with new school identifiers and templateVersion standard-v2; admission-form DTO adds school identity fields. Preserve old standard-v1 decryption compatibility.

**API/routes/contracts, validation and authorization:** Update GET /operator/students/:id/admission-form DTO with school identifiers. Keep platform TC existing issue/download contract; new template version opt-in after readiness. Do not accept UDISE data from operator when rendering PDF.

**Frontend screens, backend service orchestration, ports/facades and processing algorithm:** Remove student field and request property only in form, adapt validation for older clients to ignore deprecated optional value. Shared SchoolInfoPublicFacade; render school codes under school header in print page and TC worker; include actor school for consistency. UI verification on A4 and mobile preview.

**Errors, edge cases, reconciliation and recovery design:** Historical v1 PDFs may lack codes and must remain stored; avoid duplicate student UDISE in print. Legacy student private fields unaffected. TC fee clearance DC-02 adds gating later.
